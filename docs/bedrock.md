# Amazon Bedrock configuration

The application reads the Bedrock bearer token only from the process environment. Do not place it in source control, a frontend variable, or a browser request.

## Models

- Narrative model: Amazon Nova Lite (default: amazon.nova-lite-v1:0)
- Embedding model: Amazon Titan Text Embeddings V2 (default: amazon.titan-embed-text-v2:0)
- Vector collection: ksp_case_chunks_bedrock_v1

## Setup

Activate the project environment, set the token in the terminal that runs the backend, and index the database:

    cd /Users/arnavraj/KSPIC
    source .venv/bin/activate
    export AWS_BEARER_TOKEN_BEDROCK='your-key'
    export AWS_REGION='us-east-1'
    export QDRANT_URL='http://127.0.0.1:6333'
    python3 -m backend.ingest_qdrant
    npm run dev:backend

The indexing process creates a 1,024-dimensional, normalized Titan vector for each FIR/evidence document. It is repeatable: rerunning the command replaces the dedicated Bedrock collection with a fresh index.

## Retrieval controls

Qdrant is used only for open-ended semantic candidate retrieval. The application fetches each candidate again from SQLite before presenting it. Structured filters, all numeric counts, confidence labels, and citations remain generated by parameterized SQL and source records. Amazon Nova Lite may add a short narrative note but cannot alter those database facts.
